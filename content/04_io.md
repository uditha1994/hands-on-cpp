## Streams: data flowing in and out

C++ treats input and output as **streams**: flows of characters, one after another, like water in a pipe.

- `cout` is the **output stream** connected to the screen. You push data into it with `<<`.
- `cin` is the **input stream** connected to the keyboard. You pull data out of it with `>>`.

A memory trick: the arrows point in the direction the data moves. `cout << x` sends `x` **towards** `cout`. `cin >> x` takes data **from** `cin` and puts it **into** `x`.

```flow
flowchart LR
  K[Keyboard] --> CIN["cin"] -- ">>" --> V["your variable"]
  V2["your variable"] -- "<<" --> COUT["cout"] --> S[Screen]
```

## Reading input with cin

```cpp run title=age.cpp
#include <iostream>
using namespace std;

int main() {
    int age;
    cout << "Enter your age: ";    //@ always prompt first
    cin >> age;                    //@ wait for the user, then store the number
    cout << "Next year you will be " << age + 1 << endl;
    return 0;
}
```

```output
Enter your age: [[19]]
Next year you will be 20
```

When the program reaches `cin >> age;` it **stops and waits** until the user types something and presses Enter.

:::watch
**Always print a prompt before reading input.** A program that silently waits for input looks frozen. Notice that the prompt ends with `": "` and **no** `endl`, so the user types on the same line as the question.
:::

### Reading several values

You can chain `>>` to read several values at once. The user can separate them with spaces, tabs or Enter.

```cpp run title=item_total.cpp
#include <iostream>
using namespace std;

int main() {
    double price;
    int qty;
    cout << "Enter unit price and quantity: ";
    cin >> price >> qty;
    cout << "Total: Rs. " << price * qty << endl;
    return 0;
}
```

```output
Enter unit price and quantity: [[230.50 4]]
Total: Rs. 922
```

## How cin really works: the input buffer

When you type, your characters do not go straight into your variable. They go into a waiting area called the **input buffer**. Nothing is sent until you press Enter. Then `cin >>` reads from the buffer like this:

1. **Skip** any leading whitespace (spaces, tabs, newlines).
2. **Read** characters as long as they make sense for the variable's type.
3. **Stop** at the first character that does not fit, such as a space, and **leave it in the buffer**.

That third point explains a lot of strange behaviour. Suppose the user types `Fathima Rizwan` and presses Enter:

```cpp run title=name_word.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string name;
    cout << "Enter your full name: ";
    cin >> name;
    cout << "Hello, " << name << "!" << endl;
    return 0;
}
```

```output
Enter your full name: [[Fathima Rizwan]]
Hello, Fathima!
```

`cin >>` stopped at the space. `" Rizwan\n"` is still sitting in the buffer, waiting for the next read.

## Reading a whole line with getline

To read everything up to the end of the line, spaces included, use `getline`:

```cpp run title=name_line.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string name;
    cout << "Enter your full name: ";
    getline(cin, name);
    cout << "Hello, " << name << "!" << endl;
    return 0;
}
```

```output
Enter your full name: [[Fathima Rizwan]]
Hello, Fathima Rizwan!
```

`getline(cin, name)` reads characters until it reaches the newline (`\n`) from Enter. It **removes** that newline from the buffer but does not store it in `name`.

## The famous getline trap

This is one of the most searched beginner C++ problems on the internet. Watch:

```cpp run title=trap.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int qty;
    string item;
    cout << "Quantity: ";
    cin >> qty;                  //@ leaves the Enter key's newline in the buffer
    cout << "Item name: ";
    getline(cin, item);          //@ reads that leftover newline immediately!
    cout << qty << " x [" << item << "]" << endl;
    return 0;
}
```

```output
Quantity: [[3]]
Item name: 3 x []
```

The program did not even wait for the item name. Why? After `cin >> qty` read the `3`, the newline from pressing Enter was **still in the buffer**. `getline` saw it, thought "that's the end of an empty line", and returned an empty string.

:::brain
Draw the input buffer as a row of boxes. After the user types `3` and presses Enter, what is in each box? What does `cin >> qty` take? What does it leave? What does `getline` then see?
:::

The fix is to throw away the leftover newline before calling `getline`. Use `cin.ignore`:

```cpp run title=trap_fixed.cpp
#include <iostream>
#include <string>
#include <limits>
using namespace std;

int main() {
    int qty;
    string item;
    cout << "Quantity: ";
    cin >> qty;
    cin.ignore(numeric_limits<streamsize>::max(), '\n');  //@ discard the rest of the line
    cout << "Item name: ";
    getline(cin, item);
    cout << qty << " x [" << item << "]" << endl;
    return 0;
}
```

```output
Quantity: [[3]]
Item name: [[Coconut Oil]]
3 x [Coconut Oil]
```

`cin.ignore(n, '\n')` throws away up to `n` characters, stopping after it removes a newline. `numeric_limits<streamsize>::max()` (from `<limits>`) means "as many as there are". You will often see the shorter `cin.ignore();`, which discards just **one** character. It works when the only leftover is the newline, but the long version also cleans up anything extra the user typed, so it is safer.

:::nodumb
Q: Is there another fix?
A: Yes. `getline(cin >> ws, item);` uses the `ws` manipulator to skip all leading whitespace, including the leftover newline, before reading the line. It is neat, but be aware that it also skips any spaces the user typed at the start of their line, and it would skip a blank line entirely.

Q: When do I need to worry about this?
A: Whenever a `getline` comes **after** a `cin >>` in your program. If you only ever use `cin >>`, or only ever use `getline`, there is no problem.
:::

## Making numbers look right: iomanip

`cout` has sensible defaults, but they are not always what you want for money or tables. The `<iomanip>` header gives you **manipulators**, special values you send to `cout` to change how things are printed.

### Two decimal places: fixed and setprecision

```cpp run title=money.cpp
#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    double price = 230.5;
    cout << price << endl;                                 //@ default
    cout << fixed << setprecision(2) << price << endl;     //@ money format
    cout << 1999.999 << endl;                              //@ still in effect
    return 0;
}
```

```output
230.5
230.50
2000.00
```

- `fixed` means "use normal decimal notation, never scientific notation like `1.2e+06`".
- `setprecision(2)` together with `fixed` means "exactly 2 digits after the decimal point".
- These settings are **sticky**. They stay in effect for all later output until you change them.
- The value is **rounded** for display. 1999.999 shows as 2000.00. The variable itself is not changed.

:::watch
Without `fixed`, `setprecision(n)` means **n significant digits in total**, not n decimal places. `cout << setprecision(2) << 230.5;` prints `2.3e+02`. For money, always use `fixed` and `setprecision(2)` together.
:::

### Columns: setw, left and right

`setw(n)` sets the **width** of the next item only. The item is padded with spaces to fill `n` characters. Numbers are right-aligned by default; `left` and `right` change that.

```cpp run title=columns.cpp
#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    cout << "[" << setw(8) << 42 << "]" << endl;
    cout << "[" << left << setw(8) << 42 << "]" << endl;
    cout << "[" << right << setw(8) << "Rice" << "]" << endl;
    cout << setfill('0') << setw(5) << 42 << endl;   //@ pad with zeros
    return 0;
}
```

```output
[      42]
[42      ]
[    Rice]
00042
```

:::watch
`setw` is **not** sticky. It only affects the very next value printed. `left`, `right`, `fixed`, `setprecision` and `setfill` **are** sticky.
:::

## Worked example: the Ruwan Stores receipt

Let's combine everything: prompts, mixed input, a calculation and formatted output.

```cpp run title=receipt.cpp
#include <iostream>
#include <iomanip>
#include <string>
#include <limits>
using namespace std;

int main() {
    const double SERVICE_RATE = 0.02;   // 2% card handling fee, as an example
    string customer, item;
    double unitPrice;
    int qty;

    cout << "Customer name: ";
    getline(cin, customer);
    cout << "Item: ";
    getline(cin, item);
    cout << "Unit price (Rs.): ";
    cin >> unitPrice;
    cout << "Quantity: ";
    cin >> qty;

    double subtotal = unitPrice * qty;
    double fee = subtotal * SERVICE_RATE;
    double total = subtotal + fee;

    cout << fixed << setprecision(2);
    cout << "\n========== RUWAN STORES ==========\n";
    cout << "Customer: " << customer << "\n\n";
    cout << left << setw(18) << item << right << setw(4) << qty
         << " x " << setw(8) << unitPrice << "\n";
    cout << "----------------------------------\n";
    cout << left << setw(22) << "Subtotal" << right << setw(12) << subtotal << "\n";
    cout << left << setw(22) << "Card fee (2%)" << right << setw(12) << fee << "\n";
    cout << left << setw(22) << "TOTAL" << right << setw(12) << total << "\n";
    cout << "==================================\n";
    return 0;
}
```

```output
Customer name: [[Fathima Rizwan]]
Item: [[Coconut Oil 750ml]]
Unit price (Rs.): [[690]]
Quantity: [[2]]

========== RUWAN STORES ==========
Customer: Fathima Rizwan

Coconut Oil 750ml    2 x   690.00
----------------------------------
Subtotal                   1380.00
Card fee (2%)                27.60
TOTAL                      1407.60
==================================
```

Notice the order of input: the two `getline` calls come **before** the `cin >>` calls, so the getline trap never happens. Sometimes the simplest fix for a bug is to arrange your code so the bug cannot occur.

:::sharpen Line them up

```text

```
---solution
```cpp run title=table.cpp
#include <iostream>

int main() {
    cout << fixed << setprecision(2);
    cout << left << setw(10) << "Item" << right << setw(6) << "Qty" << setw(10) << "Price" << endl;
    cout << left << setw(10) << "Rice" << right << setw(6) << 2 << setw(10) << 460.0 << endl;
    cout << left << setw(10) << "Dhal" << right << setw(6) << 1 << setw(10) << 320.0 << endl;

```

```output
Dhal           1    320.00
```
The item names are left-aligned in 10 characters. The numbers are right-aligned so their last digits line up, which is how numbers in tables should always look.
:::

## When the user types nonsense

What happens if the program expects a number and the user types `abc`?

```cpp run title=bad_input.cpp
#include <iostream>
using namespace std;

int main() {
    int qty = 5;
    cout << "Quantity: ";
    cin >> qty;
    cout << "qty is now " << qty << endl;
    cout << "cin failed? " << cin.fail() << endl;
    return 0;
}
```

```output
Quantity: [[abc]]
qty is now 0
cin failed? 1
```

Three things happened:

1. `cin` could not turn `abc` into an `int`, so the read **failed**. Since C++11, the variable is set to 0 when this happens.
2. `cin` went into a **fail state**. While it is in that state, **every later `cin >>` is ignored**, and your program races through the rest of its prompts without waiting.
3. The characters `abc` are **still in the buffer**.

To recover, you must do two things: **clear** the fail state, then **ignore** the bad characters.

```cpp run title=recover.cpp
#include <iostream>
#include <limits>
using namespace std;

int main() {
    int qty;
    cout << "Quantity: ";
    cin >> qty;
    if (cin.fail()) {
        cin.clear();                                          //@ 1. reset the error flag
        cin.ignore(numeric_limits<streamsize>::max(), '\n');  //@ 2. throw away the bad input
        cout << "That was not a number. Using 1." << endl;
        qty = 1;
    }
    cout << "Quantity: " << qty << endl;
    return 0;
}
```

```output
Quantity: [[two]]
That was not a number. Using 1.
Quantity: 1
```

This uses an `if` statement, which you will learn properly in Chapter 7. In Chapter 8 you will combine it with a loop that keeps asking until the user types something valid. That pattern, called **input validation**, is a sign of a professional program.

:::industry
Real users type everything: letters into number fields, negative quantities, emojis, nothing at all. A large number of security problems and crashes in real software start with input the programmer did not expect. Professional developers have a saying: **never trust user input**. Always check it.
:::

:::nodumb
Q: What happens if the user types 12abc for an int?
A: `cin >>` reads the `12` successfully and stops at the `a`. The read succeeds, so there is no fail state, but `abc` stays in the buffer and the **next** read will choke on it. This is another reason to clean up the rest of the line with `cin.ignore(...)` after reading a number.

Q: What if the user types 3.7 for an int?
A: `cin >>` reads `3` and stops at the `.`, leaving `.7` in the buffer. The next `cin >>` into an `int` then fails, because `.` cannot start an integer. Reading into a `double` would read `.7` happily as 0.7. Input is full of surprises, so test your programs with strange inputs.
:::

:::compiler
This program should read an age and then a full address. Will it work as expected? If not, why not, and how would you fix it?

```cpp error
#include <iostream>
#include <string>
using namespace std;

int main() {
    int age;
    string address;
    cout << "Age: ";
    cin << age;
    cout << "Address: ";
    getline(cin, address);
    cout << age << ", " << address << endl;
    return 0;
}
```
---solution
There are two problems.

1. **Compile error:** `cin << age` uses the wrong operator. Input uses the extraction operator `>>`: `cin >> age;`.
2. **Logic error (the getline trap):** after `cin >> age`, the newline is still in the buffer, so `getline` reads an empty address immediately. Add `cin.ignore(numeric_limits<streamsize>::max(), '\n');` (and `#include <limits>`) before the `getline`, or read the address first.

:::lab The online order calculator
Uncle Ruwan wants to start taking phone orders with home delivery.

1. Ask for the customer's **full name** (may contain spaces) and **delivery address** (may contain spaces).
2. Ask for the **order value** in rupees (a decimal number).
3. Delivery costs a flat **Rs. 350**. Store it as a constant.
4. Print a neatly aligned summary showing the order value, delivery charge and grand total, all with exactly two decimal places.
5. Test with an address like `No. 7, Temple Road, Kandy`. Then test what happens if you type `five hundred` for the order value.
---solution
```cpp run title=order.cpp
#include <iostream>
#include <iomanip>
#include <string>
using namespace std;

int main() {
    const double DELIVERY = 350.0;
    string name, address;
    double orderValue;

    cout << "Customer name: ";
    getline(cin, name);
    cout << "Delivery address: ";
    getline(cin, address);
    cout << "Order value (Rs.): ";
    cin >> orderValue;

    double total = orderValue + DELIVERY;
    cout << fixed << setprecision(2);
    cout << "\nDeliver to: " << name << "\n" << address << "\n\n";
    cout << left << setw(16) << "Order value" << right << setw(10) << orderValue << "\n";
    cout << left << setw(16) << "Delivery" << right << setw(10) << DELIVERY << "\n";
    cout << left << setw(16) << "Grand total" << right << setw(10) << total << "\n";
    return 0;
}
```

```output
Customer name: [[Nimal Silva]]
Delivery address: [[No. 7, Temple Road, Kandy]]
Order value (Rs.): [[2450.5]]

Deliver to: Nimal Silva
No. 7, Temple Road, Kandy

Order value        2450.50
Delivery            350.00
Grand total        2800.50
```
Both text inputs are read with `getline` **before** the number, so there is no leftover-newline problem. If you type `five hundred`, the read fails, `orderValue` becomes 0, and the program prints a grand total of 350.00. That is a wrong answer delivered with total confidence, which is exactly why input validation matters.
:::

:::bullets
- `cout <<` sends data to the screen; `cin >>` reads data from the keyboard into a variable.
- Always **prompt** before reading. End prompts with `": "` and no newline.
- `cin >>` skips leading whitespace, reads one "word" or number, and **leaves the rest in the buffer**.
- `getline(cin, s)` reads a whole line, spaces included.
- After `cin >>`, call `cin.ignore(numeric_limits<streamsize>::max(), '\n')` before a `getline`.
- For money, use `fixed` and `setprecision(2)` (from `<iomanip>`). `setw` sets the width of the **next** item only.
- Bad input puts `cin` into a **fail state**. Recover with `cin.clear()` then `cin.ignore(...)`. Never trust user input.
:::
